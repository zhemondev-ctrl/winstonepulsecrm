# অফলাইন কল সিঙ্ক — টেস্ট পরিকল্পনা (Android + CRM)

উদ্দেশ্য: প্রমাণ করা যে (১) ইন্টারনেট না থাকলে কলের তথ্য ফোনে থেকে যায়, (২) নেট ফিরলে নিজে থেকে পাঠানো হয়, (৩) একই কল কখনো দুবার গণনা হয় না।
নিয়ম: শুধু sandbox APK বা staging ব্যবহার; লাইভ ডেটাবেসে পরীক্ষা নয় (tests/staging লাইভ ref প্রত্যাখ্যান করে)। ফলাফল docs/ANDROID_RELEASE_READINESS.md-এ ডিভাইস প্রমাণসহ লিখতে হবে।

## ক) স্বয়ংক্রিয় টেস্ট (প্রতি পরিবর্তনে চালাতে হবে)

| # | কী যাচাই | বিদ্যমান টেস্ট |
|---|---|---|
| A1 | কল-লগ কার্সর শুধু সাইন-ইন এজেন্ট থাকলে এগোয়; অফলাইনে এন্ট্রি হারায় না | `CallLogCursorTest.kt`, `SessionAndQueueRulesTest.kt` |
| A2 | নেটওয়ার্ক/408/429/5xx = পুনরায় চেষ্টা; 400/403/404/409/410 = স্থায়ী ব্যর্থ | `SyncErrorClassifierTest.kt` |
| A3 | নেট ফিরলে শুধু প্রথম চেষ্টা পার হওয়া ENQUEUED কাজ একই নামে (REPLACE) পুনরায় যায়; চলমান/শেষ কাজ আবার যায় না | `ReportReplayTest.kt` |
| A4 | অন্য এজেন্টে সাইন-ইন হলে পুরোনো সারির কাজ বাতিল; call_uid enqueue-এ স্থির | `SessionAndQueueRulesTest.kt`, `QueuedAudioIdentityTest.kt` |
| A5 | অ্যাপ বন্ধ হয়ে আবার চালু হলেও একই call id থাকে | `ActiveCallSnapshotTest.kt`, `CallLifecycleTest.kt` |
| A6 | সার্ভারে একই কল-ইতিহাস ইভেন্ট একবারই লেখা হয় (`lead_event:<id>:<kind>`) | `tests/call-history-once.test.ts` |
| A7 | দেরিতে আসা কল-লগ শুধু একমাত্র মিল থাকা একই-এজেন্ট সারিতে বসে; `call_log_id` একবারই; দ্ব্যর্থ হলে মেলানো হয় না | `tests/call-log-reconcile.test.ts` |
| A8 | রিং হওয়া সময় talk time নয়; কল-লগ প্রমাণ ছাড়া connected নয় | `CallHistoryEvidenceTest.kt`, `tests/call-evidence.test.ts`, `tests/phone-measured-call.test.ts` |
| A9 | sandbox ড্রিল লাইভে কিছু লেখে না (liveWrites 0) | `SyncFailureDrillTest.kt`, `tests/sync-failure-drill.test.ts` |

চালানো: `bunx vitest run tests/call-history-once.test.ts tests/call-log-reconcile.test.ts tests/call-evidence.test.ts tests/phone-measured-call.test.ts tests/sync-failure-drill.test.ts` এবং `android/` থেকে `./gradlew testSandboxDebugUnitTest`।

ঘাটতি (নতুন টেস্ট যোগ করা উচিত):
- A10: একই call_uid দিয়ে outcome দুবার পাঠালে সার্ভার দ্বিতীয়টিকে নতুন কল হিসেবে না গোনে (KPI কল সংখ্যা ১ থাকে)।
- A11: একই CallLog `_ID` দুবার স্ক্যান হলে (কার্সর রিসেট) দ্বিতীয়বার কাজ সারিতে না ওঠে।

## খ) ডিভাইসে হাতে-কলমে টেস্ট (sandbox APK, আসল ফোন)

প্রতিটির জন্য লিখুন: ফোন মডেল, Android সংস্করণ, APK সংস্করণ, সময় (ঢাকা), ফলাফল, স্ক্রিনশট।

| # | ধাপ | প্রত্যাশিত ফল |
|---|---|---|
| D1 | Airplane mode চালু → লিডে কল (উত্তর দেওয়া) → রিপোর্ট জমা | ফোনে "অপেক্ষমাণ" দেখায়; কিছু হারায় না; CRM সংযোগ স্ট্রিপ "connected" দেখায় না |
| D2 | অফলাইনে আরও ২টি কল (একটি না-ধরা, একটি ব্যস্ত) | তিনটিই সারিতে আলাদা call id নিয়ে থাকে |
| D3 | অফলাইন অবস্থায় অ্যাপ জোর করে বন্ধ, ফোন রিস্টার্ট | রিস্টার্টের পরও তিনটি কাজ সারিতে থাকে |
| D4 | নেট চালু | কয়েক মিনিটের মধ্যে সব পাঠানো হয় (ঘণ্টার backoff অপেক্ষা নয়) |
| D5 | CRM-এ লিডের ইতিহাস দেখুন | প্রতিটি কল ঠিক একবার; উত্তর দেওয়া কলে কল-লগের talk time, না-ধরা কলে ০ |
| D6 | নেট অন/অফ দ্রুত ৫ বার টগল | কোনো কল দুবার দেখা যায় না; KPI কল সংখ্যা বাড়ে না |
| D7 | অফলাইনে কল → সাইন-আউট → অন্য এজেন্টে সাইন-ইন → নেট চালু | আগের এজেন্টের কাজ নতুন এজেন্টের নামে যায় না |
| D8 | কল-লগ পারমিশন বন্ধ করে কল → পরে পারমিশন দিন | কল "যাচাই হয়নি" থাকে, পারমিশন পরে আবার চেষ্টা হয়; ভুয়া connected নয় |
| D9 | ৯:০৫ ব্রিফিং স্বীকার না করে অফলাইনে কাজ → নেট চালু | সার্ভার প্রত্যাখ্যান করে; এজেন্টকে বার্তা দেখায়; বারবার চেষ্টা করে না |
